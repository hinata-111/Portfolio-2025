# riochin.dev 型レイアウト 設計書

日付: 2026-10-22
参考: https://riochin.dev/ja (2026-10-21 時点を Playwright で実測)

## 目的

「スクロールしても情報が多すぎて読み疲れる」状態を解消する。トップページを要約だけにし、詳細は下層ページへ移す。

## 方針

- 真似るのは **骨組み(並べ方)とサイズ** だけ。配色・宇宙背景(`CosmicBackground`)・フォントは現行のまま
- **文言は変えない**。トップから外した詳細は `/about` と `/works` にそのまま載せる
- ページ構成: `/`(トップ)・`/about`・`/works`。経歴は 7 行と短いため専用ページを作らない
- 追加のクライアントコンポーネントは作らない。スマホのメニュー開閉は `<details>` で行う

## ページ構成

### トップ `/`

0. サイトナビ(参考サイトと同じ左サイド配置)。項目は About(`/about`)/ Works(`/works`)/ Contact(`#contact`=今いるページ末尾へスクロール)の 3 つ。経歴は About に含めるためナビに置かない
   - 1100px 以上: 左サイドに縦並びで全ページ固定(left 48px・幅 184px)。右端に GitHub・メールの縦レールを固定(right 48px、アイコン 28px)。本文側は `padding-left: 248px` / `padding-right: 120px`
   - 721〜1099px: 上部の sticky バー(右端に GitHub・メール)
   - 720px 以下: 固定ヘッダー 63px(ロゴ・GitHub・メール・`<details>` メニュー)
1. ヒーロー: **従来の全画面演出のまま**(キャッチコピー・導入文・肩書き・軌道・スクロールマーカー。氏名と所属の署名欄はプロフィール欄と重複するため削除)。riochin の「中央パネル + 左右カラム」は採用しない(2026-10-22 ユーザー判断)
2. プロフィール: 丸写真 80px・氏名・所属・「自己紹介を読む →」(導入文と肩書きはヒーローにあるため繰り返さない)
3. 経歴: 日付 + 見出しの 1 行リスト(説明文は `/about` で表示)
4. 活動: 作品カード(サムネ + タイトル)のグリッド + 「すべての活動を見る →」
5. コードの外側: 同じ作品カードのグリッド
6. Contact: メールボタン(`/about`・`/works` の末尾にも同じものを置く)

作品カードは `/works#<slug>` へリンクする。

### `/about`

About(プロフィール・自己紹介全文・モットー)→ Skills → Experience(説明文つき縦タイムライン)→ Contact。

### `/works`

活動(作品台帳)→ コードの外側(エッセイ)→ Contact。小見出しラベルは両方 `Works` に統一。各作品は `id=<slug>` を持つ。

## 実測サイズ(参考サイト / 1265px 幅)

| 部位 | 値 |
|---|---|
| 本文カラム | 幅 683px(max 768px 内) |
| セクション間 | 64px |
| h2 | 22px bold、h2 → 本文 24px |
| 経歴リスト | 16px、日付と見出しの gap 16px、行間 8px |
| プロフィール | 丸アバター 80px |
| 作品グリッド | 4 列、gap 16px、サムネ 16:9 |
| スマホ(390px) | 固定ヘッダー 63px + 44px メニューボタン、左右余白 24px、作品グリッド 2 列 |

本サイトでの対応: h2 は `--fs-title`(最大 22px)、本文 `--fs-body` 16px、`--space-section` 32px(上下合計でセクション間 64px)、`--space-heading` 24px。

## データ

`Project` と `BeyondItem` に `slug` を追加する: `tabime` / `internship` / `fukushima` / `travel` / `radio` / `comedy`。
