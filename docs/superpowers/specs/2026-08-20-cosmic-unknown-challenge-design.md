# Cosmic Unknown Challenge Design Specification

## 1. 目的と中心概念

この仕様は、ポートフォリオを「作品情報の間を未知の形が漂う」体験として設計するための基準を定める。宇宙は装飾や舞台設定ではなく、まだ知らない領域の比喩である。作品と経験はこれまで未知へ挑戦してきた軌跡、閲覧とスクロールは次の可能性へ踏み出す行為として扱う。

合意した表現は「静かな漂流」とする。画面全体に過剰な演出を加えず、作品情報を主役にしたまま、意味を固定しない形が余白をゆっくり横切ることで、未知への好奇心と挑戦の余韻をつくる。

本仕様は、既存の `docs/superpowers/specs/2026-07-26-cosmic-background-design.md` と視覚・背景表現が競合する場合に優先する。ただし、現在のセクション名、順番、コピー、既存のコンテンツ挙動は変更せず、既存コンテンツの意味や機能も維持する。デプロイ、コンテンツ変更、公開設定変更はこの仕様の範囲外とする。

## 2. 形状カタログと素材

表示できる未知の形は、次の5種類だけに固定する。

1. 中空ガラスリング
2. 欠けた球／クレセント
3. 斜めの三角柱
4. 不規則な結晶片
5. 融合した二重泡

「引き伸ばした液滴」は明示的に除外する。旧仕様にあるランダム生成の10種類カタログ、旧カタログ由来の色違い、5種類以外の図形もすべて除外する。表示ごとのランダム選択は行わず、形状・配置・大きさ・奥行き・初期値を固定定義する。

全形状は、透明で発光を含むガラス質の統一素材とする。形ごとに固有の色、役割、技術、作品、感情などの意味を割り当てない。形の解釈は閲覧者に委ね、未知と可能性を感じる余白を残す。発光は輪郭や反射のごく淡い変化に限定し、強いネオン表現や多色の演出は使わない。

## 3. 配置と共存

### 3.1 数量と配置

- デスクトップでは、同一ビューポート内に見える形状の上限を5個とする。ページ全体に配置する総数の上限ではない。
- Hero は Lサイズ1個、Mサイズ2個、Sサイズ2個の構成とする。
- Hero以外は、各セクションの同一ビューポート内で2〜3個までとする。
- モバイルでは、同一ビューポート内に見える形状の上限を3個とする。狭い画面ではサイズと密度を下げ、本文の連続性を優先する。
- 配置は固定のレイアウト定義から決定し、SSRとクライアントで一致する決定論的な値にする。
- 図形は本文、見出し、リンク、ボタン、フォーム、カードの操作領域に重ねない。図形の外周から文字・操作対象まで最低40pxのクリアランスを確保する。
- 画面端や切り抜きは許容するが、操作対象を隠す切り抜きは許容しない。

### 3.2 本文との共存

Heroは囲みやカードを使わず、文字と形を宇宙空間に直接浮かせる。About、Skills、Beyond Code、Contactも開いた構成とし、全面的なカード化を行わない。情報量が多い Experience と Projects のみ、ほぼ無色のネイビーによる薄い透明ガラス面を使用できる。枠線の発光や強い境界線は使わない。

セクションの区切りは、余白と背景の明度差でつくる。格子線、軌道線、装飾的な区切り線には依存しない。現在の順番は次のまま固定する。

`Hero → About → Skills → Experience → Projects → Beyond Code → Contact`

## 4. 動きと強度

標準強度は B とする。演出は自律的な漂流とスクロールに連動した奥行きを組み合わせる。

- 自律漂流の周期は15〜20秒とし、目立たない速度で位置と明度を連続的に変化させる。
- スクロールに連動して遠景・中景・近景の移動率を変え、奥行きだけを穏やかに感じさせる。
- 中空ガラスリング、斜めの三角柱、不規則な結晶片の回転は最大6度までとする。
- 欠けた球／クレセントと融合した二重泡は回転させない。
- 画面内にある形だけが、ごく淡い発光を変化させる。視界外で発光を維持し続けない。
- 瞬間的な拡大、急加速、点滅、視線を奪う衝突表現は行わない。

実装は `requestAnimationFrame`（rAF）で描画タイミングを統合し、毎回のスクロールイベントから直接スタイルを書き換えない。スクロール監視は passive とし、`IntersectionObserver` で画面外の形を停止する。画面外停止から復帰するときに位置が不連続に跳ねないよう、経過時間を補正する。低性能端末では自律漂流の更新頻度と発光計算を下げてもよいが、本文の表示と操作性を優先する。

`prefers-reduced-motion: reduce` が有効な場合は漂流、スクロール連動、回転、発光変化を停止し、決定論的な静止配置だけを表示する。静止状態でも形のコントラスト、本文、操作対象は成立させる。

## 5. 構成と実装境界

次の責務を分離する。

- 形状定義・配置定義：5種類の形、サイズ、初期位置、奥行き、透明度、許可された回転を静的データとして保持する。
- レイヤー：星、形状、コンテンツを別レイヤーに分け、形状がコンテンツのレイアウトやフォーカス順を変更しない。
- 形状レンダラー：定義を受けてガラス素材を描画する。表示数の制約、`aria-hidden`、クリック透過をここで保証する。
- スクロールコントローラー：スクロール量、rAF、奥行き係数、IntersectionObserver、reduced-motion 状態だけを扱う。コンテンツコンポーネントから独立させる。
- コンテンツ：現在のセクション名、順番、コピー、既存のコンテンツ挙動を保持する。装飾レイヤーの失敗で本文が失われない。

初期値とレイアウトはSSR-safeな決定論的値とし、ハイドレーション後に別の形や位置へ置き換えない。JavaScriptが無効、描画が失敗、サイズ計算が取得できない場合は、本文と操作対象を通常の静的レイアウトで表示し、装飾形状だけを省略する。装飾レイヤーの例外はコンテンツ描画や操作を停止させず、コンソールへ予期しないエラーを残さない。

## 6. アクセシビリティとパフォーマンス

形状、星、発光、装飾ガラスは意味を持たないため `aria-hidden="true"` とし、キーボードフォーカス、読み上げ順、ポインター操作の対象にしない。形状レイヤーは `pointer-events: none` を基本とする。本文と操作対象には、装飾に依存しない十分な色コントラストとフォーカス表示を確保する。

アニメーションは単一のrAFループに集約し、不要なレイアウト計算や大きな常時更新を避ける。画面外停止、モバイル上限3個、reduced-motion静止化により、装飾がコンテンツの読み込み・入力・スクロールを阻害しない。描画負荷が高い環境では発光を無効化してもよく、その場合も形状の静止表示とコンテンツの完全性を保つ。

## 7. TDDと受け入れ確認

実装前に次のREDテストを用意し、実装後にGREENを確認する。既存のコンテンツ不変条件も同じ検証ループに含める。

- カタログに存在する形が、指定した5種類だけである。
- 「引き伸ばした液滴」、旧ランダム10種類カタログ、旧多色カタログ由来の形が存在しない。
- デスクトップでHeroがL1・M2・S2、同一ビューポート内の表示が最大5個である。
- モバイルで同一ビューポート内の表示が最大3個である。
- 形状と本文・操作対象の距離が最低40pxである。
- 格子線、軌道線、装飾的な区切り線が描画されない。
- 形状・星・発光の装飾レイヤーが `aria-hidden` で、フォーカスやクリックを奪わない。
- セクション名、順番、コピー、既存コンテンツ挙動が `Hero → About → Skills → Experience → Projects → Beyond Code → Contact` のまま保たれる。
- reduced-motion環境で漂流、連動、回転、発光変化が停止し静止表示になる。
- rAF、passive scroll、IntersectionObserverによる画面外停止が機能する。
- 形状の描画失敗時も本文と操作対象が表示される。
- ビルドと既存テストが成功する。
- デスクトップとモバイルのブラウザ確認で、重なり、可読性、数量、動き、操作性に問題がない。
- ブラウザのコンソールにエラーがない。

この仕様の完了条件は、上記のローカル検証が通り、現行コンテンツが変わっていないことを確認することとする。デプロイ、本番検証、コンテンツの加筆・削除は別途承認された作業として扱う。
