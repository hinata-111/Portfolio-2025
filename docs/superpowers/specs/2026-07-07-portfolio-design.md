## 1. 目的とターゲット

- 28卒就活用ポートフォリオ。時期・選考段階を問わず汎用的に使う(ES添付URL〜最終面接まで)
- 閲覧者: エンジニア / クリエイター / ビジネス職の面接官すべてに対応する単一サイト
- 志望業界: エンタメ・空間体験系(USJ、OLC、teamLab)、都市開発・デベロッパー系(三井不動産、三菱地所)、冬に吉本興業・広告代理店・メガベンチャー(CyberAgent 等)
- 一貫した軸: 「人を笑顔にし、心を動かすものを生み出す」

## 2. 形式

- **自作 Web サイト**(フルスクラッチ)。サイト自体を技術力・UI/UX 力の証明とする
- 推奨技術: Next.js + Tailwind CSS + Framer Motion、Vercel でデプロイ
- 構成はエンジニア型のシンプルなポートフォリオ。特定の一作品を推すのではなく、技術スタック・経歴・実績を網羅的に示す

## 3.5 デザイン方向(v4 確定)

### コンセプト: 「夜のステージとスポットライト」× ソフト&ラウンド
暗幕のダークネイビーに、アンバー(スポットライト)が「笑顔」を照らす。漫才・ラジオ・エンタメ志望との一貫性。参考: umao(温かみ・大きな角丸・円形マスク)× Effortel(ダークのプロ感・番号/時系列・ピルUI・セクションパネル構造)。v3で「カクカクして硬い」フィードバック → v4で全面的に角丸・ピル化して解消。

### デザイントークン(v4)
- アクセント: `--sun: #FFC53D` / `--sun-deep: #E8A013`(アンバー=スポットライト)
- ダーク(デフォルト): 地 `#101722`、パネル `#18202E`、面 `#202A3B`、文字 `#E8EAF0`、罫線 `#2B3750`、muted `#93A0B4`
- ライト: 地 `#F4F2EC`、パネル `#FBFAF6`、面 `#FFFFFF`、文字 `#232D3F`、罫線 `#E3DFD3`
- 角丸: `--radius-xl: 32px`(セクションパネル)/ `--radius-lg: 22px`(カード)/ `--radius-md: 16px` / ボタン・タグ・バッジ=ピル(999px)
- タイポ: キャッチコピー=明朝(Hiragino Mincho / Yu Mincho)、本文=ゴシック、ラベル・番号=monospace
- 構造: Heroセンター寄せ巨大タイポ(最大64px)+`⌊ ラベル ⌉`mono飾り。各セクションは角丸32pxの大パネル(panelbox)で包む。上部に浮遊ピルナビ(すりガラス、Contact=黄色CTA)
- モチーフ: 黄色マーカーハイライト(スイープ演出)、Heroのスポットライトグラデーション、Skillsのアイコンチップ(Py/AI/TS等)
- セクション 01〜06 番号管理。Experience=ドット+縦線タイムライン(スクロールで点灯)
- モーション: Hero時間差登場→マーカースイープ(0.95s/1.2s)、スクロールリビール(IntersectionObserver)、カードホバー浮上+アンバー光、全て prefers-reduced-motion 対応
- モックアップ: `docs/design/portfolio-mockup-v7.html` / Artifact「v7-hero-stage」

### v6〜v7 での確定変更(2026-07-07)
- **レイアウト**: セクションの大パネル箱を撤去 → 余白+中央フェード区切り線の開放レイアウト。本文最大幅880px
- **ナビ**: 上部ナビ削除 → 右下固定「Contact →」ピル(contact-fab)のみ
- **About**: 2カラム(左=正方形写真200px+基本情報リスト[名前/所属/研究/趣味]、右=ストーリー2段落)+末尾に座右の銘ブロック
- **座右の銘(論語・雍也)**: 「之を知る者は之を好む者に如かず、之を好む者は之を楽しむ者に如かず」→「楽しむ者」宣言。Contact見出しは「一緒に楽しみましょう」で呼応
- **Skills**: カテゴリ行(chip+カテゴリ名+使用文脈)+技術名ピルの一覧形式
- **Hero演出(v7)**: ①開幕スポットライト点灯(brightness 3→1)②Canvas粒子55個(舞台の埃、マウスパララックス)③ステージLED風ティッカー「MAKE THEM SMILE/笑顔/MOVE THEIR HEART/心」(アウトライン+塗り交互)④カーソル追従スポットライト(pointer:fineのみ)
- **遊び心**: console隠しメッセージ(スポットライトASCII+論語+「楽しむ者」宣言+連絡呼びかけ)
- **実装時の品質要件**: `:focus-visible`スタイル必須 / Canvasは画面外でrAF停止(IntersectionObserver)/ mousemoveはrAFスロットリング / resizeはdebounce

### 参考サイト分析・注意点キャッチアップの反映(2026-07-07)
出典: ARUTEGA、Tracks、PERSOL の各記事+参考サイト2件(umao.co.jp / effortel.com)

- テンプレ回避・フルスクラッチ(方針どおり)。1ページ構成で情報に優劣をつける
- アニメーションは控えめ・軽量・イージング重視。デザイン過剰で内容不明確になるのは減点
- 「なぜこの技術を選んだか」の選定理由と「苦労・学び」を各 Projects に記載(面接の深掘り対応)
- デモ・スクショ・動画などの視覚素材を用意。GitHub README を充実させる
- 公開後も定期更新。放置しない

### セキュリティ・権利面の注意
- 守秘義務: 自分が開発したものでも機密該当なら掲載不可。インターン成果物は会社確認が最優先
- 個人情報: クライアント情報・個人を特定できる情報は載せない(福島の生徒写真は許諾必須、レディオ湘南メンバー情報も同様)
- 著作権: 引用・サンプルコード使用時は適切な表記。他者ポートフォリオとの類似度にも注意

## 3.6 Claude を使った UI/UX 制作フロー

- **Phase 1 デザイン探索(実装前)**: Artifact モックアップで方向性確定 → 完了(v2)。トークン文書化済み
- **Phase 2 実装**: Next.js + Tailwind でセクション単位に実装。トークンどおりに組む
- **Phase 3 視覚検証**: ブラウザ連携でスクショ取得 → モバイル/タブレット/PC × ライト/ダーク = 6パターン検証、レイアウト崩れを検出・修正
- **Phase 4 磨き**: アクセシビリティ(コントラスト・フォーカス・reduced-motion)、Lighthouse 計測・軽量化、OGP・メタ情報
