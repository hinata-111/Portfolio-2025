# Cosmic Editorial Portfolio Redesign

作成日: 2026-09-01

## 1. 目的

現在のポートフォリオは、情報量そのものではなく、角丸・枠線・半透明背景を持つ要素が繰り返されることで、次の問題が起きている。

- 初見でどこから読むべきか分かりにくい
- 重要な情報と補足情報が同じ強さに見える
- カードが規則正しく並び、スクロール中のリズムが単調になる
- 宇宙モチーフが背景装飾に寄り、内容と結びついていない
- 情報は多いが、まとまりではなく混雑として感じられる

本変更では情報を削らず、宇宙モチーフを中心に残したまま、編集記事のような強弱と流れを持つ1ページへ再構成する。

## 2. 伝える人物像

第一印象は「企画から実装まで一貫して形にする人」とする。AI・Web開発は、その能力を裏づける専門性として見せる。

優先する閲覧者は採用担当者・面接官。短時間で実績と担当範囲を確認できることを優先しつつ、エンジニア・デザイナー・協業相手にも個性が伝わる構成とする。

宇宙モチーフは次の意味を担う。

- 未知へ飛び込み、形にする探究と挑戦
- 経験や活動がつながり、現在の人物像を作る軌跡
- 神秘性や奥行きは、情報を邪魔しない範囲の演出

## 3. 採用する方向性

採用案は `Cosmic Editorial Journey`。

同じカードを反復せず、セクションごとに情報の器を変える。

- 大見出しと広い余白
- 開放された本文と段組み
- 細い罫線と番号
- 写真とキャプション
- 重要箇所だけの黄色
- 一部に限定した角丸・半透明背景

ページを宇宙旅行風のアトラクションにはしない。宇宙表現より情報取得を優先する。

### 3.1 正式なビジュアル参照

実装の視覚的な基準は[`portfolio-mockup-v9-cosmic-editorial.html`](../../design/portfolio-mockup-v9-cosmic-editorial.html)とする。

次の特徴は、実装時に別案へ置き換えずサンプルへ揃える。

- セクションごとに余白と文字サイズを変える視線誘導
- 同形カードの反復を避けた、開放的で非対称な誌面構成
- 暗い宇宙背景、細い罫線、限定的な黄色の使い方
- Project Ledger、縦タイムライン、写真章という各セクション固有の器
- Heroの黄色いマーカーと`ENGINEER × ENTERTAINMENT`の見え方

モック内で本文が省略されている場合は、本仕様の固定コピーと`app/content.ts`に存在する情報を優先する。レスポンシブではデスクトップ版を単純に縮小せず、同じ情報階層と印象を保ったまま1カラムへ再構成する。

## 4. ページ順序

最終的な順序は次のとおり。

1. Hero
2. About
3. About内のプロジェクト索引
4. 座右の銘
5. Projects
6. Skills
7. Experience
8. Projects Beyond My Work
9. Contact

ProjectsをSkills・Experienceより先に置き、「何を形にしたか」を最初に示す。その後に技術と経歴を置き、実績の裏づけとして機能させる。

SideNavは維持する。セクション順の変更に合わせて番号を更新し、現在位置とページ全体の構成を確認できる航路図として扱う。

## 5. 固定するコピーと表現

次の要素は変更しない。

### Hero

- `人を笑顔にし、心を動かすものを生み出す。`
- `ENGINEER × ENTERTAINMENT`
- `笑顔`と`心を動かす`に入る黄色いマーカー
- 黄色いマーカーが左から現れる既存の演出
- `ENGINEER × ENTERTAINMENT`の黄色表示

「企画から実装まで一貫して形にする」はHeroの主見出しを置き換えず、補助説明とページ全体の構成から伝える。

### About

- セクション名 `About`
- 見出し `プロフィール`
- 現在のプロフィール情報、ストーリー、外部リンク
- 現在のプロジェクト索引

### 座右の銘

- 引用全文
- `— 論語・雍也`
- 「楽しむ者」としてつくる宣言
- 中央揃え、黄色い引用符、背後の円形演出
- About内のプロジェクト索引の後という配置

### セクション名

- `02 / Projects` + `創作物`
- `03 / Skills` + `技術スタック`
- `04 / Experience` + `経歴`
- `05 / Projects Beyond My Work` + `コードの外側`
- `06 / Contact`

`Missions`、`Identity`、`Capability Map`、`Flight Log`などへの改称は行わない。

## 6. カードの使用ルール

カードは「独立した操作対象」「比較対象」「明確に区切る必要がある単位」に限定する。

次の箇所ではカードを撤去する。

- About全体を囲う大きなパネル
- Aboutのプロジェクト索引に並ぶ同形カード
- Projectsの外枠カードと入れ子の詳細カード
- Experienceの各経歴を囲うカード
- Projects Beyond My Workの3枚グリッドカード
- Contact全体を囲う大きなパネル

Skillsはユーザーが現行の見せ方を選択したため、例外として維持する。

## 7. セクション別デザイン

### 7.1 Hero

Heroは現在のブランドコピーと黄色演出を維持する。主見出しをページ内で最も強い文字とし、氏名・所属・役割は一段階下げる。

宇宙演出は、星・グロー・軌道をHero周辺へ集中させる。本文セクションへ同じ強さで広げない。

### 7.2 About

プロフィール写真と基本情報は開放的な2カラムにする。大きなパネルで全体を囲わず、写真、氏名、基本情報、本文の間を余白と細い罫線で分ける。

プロジェクト索引は、番号・タイトル・短い要約・下方向の矢印を持つ行として残す。角丸カードを並べず、本文からProjectsへ移る目次として機能させる。

本文の事実と情報量は維持し、段落の順序や表現は読みやすさのため再編集できる。

### 7.3 座右の銘

現在の文言と中央配置を維持する。AboutとProjectsの間の静かな間として扱うが、新しいコピーへの要約や置き換えは行わない。

### 7.4 Projects

画像、抽象イラスト、meta、tagsは追加しない。

採用する形式は `Project Ledger`。左側に3作品の索引、右側に各作品の本文を置く。作品ごとに番号と細い区切り線を用い、外枠カードは使わない。

3作品は同格に扱う。TabimeだけをFeaturedにしない。各作品の表示面積と見出しの強さは揃えるが、現在の情報量以上の長いケーススタディへは拡張しない。

表示する情報は現在のProjectデータにある次の要素を基本とする。

- タイトル
- 要約
- 現在存在する詳細
- 必要な外部リンク

削除済みのProject用metaとtagsは復活させない。`Beyond`のmeta・tagsおよびSEO metadataとは別物として扱う。

### 7.5 Skills

現行の見せ方を維持する。

- Py / TS / DB / Opsのカテゴリ行
- 略称チップ
- カテゴリ名
- 使用文脈
- 技術名ピル
- 現在のカテゴリ順と全項目

星座表示や別のスキルマップへ置き換えない。周囲のセクション間隔と背景のつながりだけを新しいページへ合わせる。

### 7.6 Experience

星座状に文字を散らす構成は採用しない。年代・出来事・説明を素早く取得できる縦タイムラインにする。

- 左に年代
- 中央に小さな黄色い点と細い縦線
- 右に出来事と説明
- 全件を時系列順に表示
- 各行をカードで囲わない

宇宙表現は黄色い点と細い線に限定する。現在の`constellation-map`による散在配置は撤去する。

### 7.7 Projects Beyond My Work

見出しは現行のまま維持する。写真と文章は削除しない。

一人旅は現在も情報量が多く`featured`であるため、大きな写真章として扱う。旅の背景、得られたこと、meta、tags、リンクを写真の下または横へ開放配置する。

ラジオと漫才は、一人旅に続く短い写真章として配置する。2枚の同形カードにはせず、写真と文章を左右交互に置く。

### 7.8 Contact

現行どおり`06 / Contact`とEmailボタンを表示する。新しいキャッチコピー、GitHub一覧、追加CTAは加えない。

大きなパネルは使わず、ページの終着点として余白を広く取る。

## 8. 情報階層

情報を削るのではなく、次の3層に分ける。

1. 主役: Hero、各セクション見出し、Projectタイトル
2. 内容: About本文、Project要約・詳細、経歴、Beyond本文
3. 補助: 番号、英語ラベル、meta、tags、外部リンク

すべてを同じ背景・枠線・文字サイズで見せない。主役は文字サイズと余白、内容は読み幅、補助は色と書体で差をつける。

## 9. 色と宇宙表現

黄色はブランド上の重要色として残すが、使用箇所を限定する。

- Heroのマーカー
- `ENGINEER × ENTERTAINMENT`
- セクション番号
- タイムラインの点
- リンクや現在位置など重要な状態

本文用の面を黄色にせず、背景・本文・罫線とのコントラストを維持する。

宇宙表現はHero、背景の深度、セクション間の軌道・星、SideNavの航路感へ使用する。情報本文を星座状に散らさない。

## 10. モーション

Heroの黄色マーカー演出は維持する。それ以外のモーションは、意味があるものに限定する。

- セクション表示: 小さな移動とopacity
- リンク・ボタン: 押下とホバーの即時フィードバック
- SideNav: 現在位置の変化
- 背景: 読書を妨げない低速・低コントラストの動き

同じ操作を頻繁に行う要素へ長いアニメーションを付けない。UIの遷移は原則300ms未満とし、`transform`と`opacity`を中心にする。

`prefers-reduced-motion`では位置移動・追従・背景アニメーションを無効化し、必要なopacity・色変化だけを短時間で残す。

## 11. レスポンシブ

### Desktop

- SideNavを表示
- Aboutは写真と本文の2カラム
- Project Ledgerは索引と本文の2カラム
- Beyondは写真と本文を左右に展開

### Tablet

- 本文幅を優先し、2カラムの比率を縮める
- SideNavが本文と重ならないことを保証する
- Project Ledgerの索引は幅を抑える

### Mobile

- すべて1カラム
- SideNavは現行のモバイル導線を維持
- Project Ledgerの左索引は本文上部の短い目次へ変換
- 年代と経歴本文が窮屈にならないよう、タイムラインの列幅を調整
- Skillsのカテゴリ行は現在のモバイル積み上げを維持
- 横スクロールを発生させない

## 12. アクセシビリティ

- 見出し階層とDOM順を視覚順と一致させる
- SideNavの`aria-current`を維持する
- すべてのリンクとボタンに`:focus-visible`を用意する
- タッチ領域は44px以上を基準とする
- 黄色と背景、本文と背景のコントラストを確認する
- 写真のaltを維持する
- 200%ズームでも情報が欠落しない
- `prefers-reduced-motion`を尊重する
- hover前提の情報表示を作らない

主な対象候補:

- SEO metadata、OGP

- Projectの長いケーススタディ追加

## 14. テスト方針

固定仕様はTDDで変更する。先に現在のテストを確認し、必要な期待値をREDにしてから実装する。

### 構造

- トップページのセクション順が設計どおり
- SideNavの番号・href・現在位置判定が新しい順序と一致
- Project Ledgerに3件すべてが表示される
- Experienceに全経歴が時系列で表示される
- Beyondに3活動と既存の詳細・リンクが残る

### 固定コピー

- Heroの主見出しと`ENGINEER × ENTERTAINMENT`
- 座右の銘全文、出典、宣言
- `Projects / 創作物`
- `Skills / 技術スタック`
- `Experience / 経歴`
- `Projects Beyond My Work / コードの外側`
- `Contact`

### 保持するUI

- Skillsのカテゴリ、順序、略称チップ、技術名ピル
- Projectのmeta・tagsが復活していない

### レスポンシブ・操作
